# PREF-0012 — Redesign the layout, not the words

**Polarity:** like
**Facet terms:** `H.VOCAB.domain-real` ✓ · `H.VOCAB.invented` ✗ · `H.VOCAB.glossary-locked` ✓
**Scope:** redesigns of existing products; any work with an established domain vocabulary
**Evidence:** on the Markito redesign Sam required the platform's real page set and vocabulary to be kept — the redesign changes layout and visual language, not names and functions (2026-10)
**Date:** 2026-10-07

**The preference.** Keep the names the product and its users already use for pages,
functions and objects. Improve structure, hierarchy and visual language instead.

**Why.** Renaming turns a redesign into a different product, and makes it impossible to
review against the original — the reviewer can no longer tell what changed. The established
vocabulary is also what the users already know.

**Exceptions.** A name that is actively wrong or misleading can be challenged — explicitly,
as a proposal with a reason, not silently in a mock-up.
